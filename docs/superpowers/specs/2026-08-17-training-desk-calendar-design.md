# 训练桌历设计规格

日期：2026-08-17  
状态：用户已批准，可进入分阶段实施计划

## 1. 产品目标

“训练桌历”是一款面向 Windows 10/11 x64 的轻量桌面健身计划组件。它长期驻留在桌面层，以连续两周日历展示计划，让用户无需打开完整管理软件即可查看、编辑和勾选每日训练。

软件优先保证低干扰、低资源占用、本地隐私和可靠恢复，不承担专业训练记录、云协作或提醒平台的职责。

## 2. 支持环境

- Windows 10 22H2 x64。
- Windows 11 x64。
- 首版界面仅提供简体中文。
- 首版不支持 ARM64、32 位 Windows、移动端或网页端。

Windows 10 已结束常规支持，因此项目只保证在 22H2 最终版本上完成兼容测试，不承诺处理更旧的 Windows 10 版本。

## 3. 核心桌面体验

### 3.1 窗口形态

- 组件为无边框桌面窗口，不显示任务栏按钮。
- 普通应用窗口会覆盖组件；组件不使用“始终置顶”。
- 程序常驻系统托盘，并且只允许运行一个实例。
- 组件可以拖动和自由缩放，也可以锁定位置与尺寸。
- 窗口位置、尺寸、锁定状态、所在显示器和背景设置在重启后恢复。
- 组件可移动到任意显示器。目标显示器断开时，组件移动到主屏幕的可见工作区。

### 3.2 日期范围

- 一周从周一开始。
- 启动时默认展示本周一至下周日，共 14 天。
- 本周和下周各占一行，每行 7 张日期卡片。
- 上一页和下一页每次移动 14 天。
- “今天”命令恢复到包含当前日期的默认两周范围。
- 历史计划长期保留，用户可以向前浏览。

### 3.3 日期卡片

每个日期只保存一份计划记录，字段包括：

- 可换行的自由文本。
- 已完成/未完成状态。
- 6 种固定任务色之一。

固定任务色采用已确认的“清晰均衡”色板：

| 编号 | 用途名称 | 色值 |
| --- | --- | --- |
| 1 | 青绿 | `#BFE3DA` |
| 2 | 蓝色 | `#C7D8F2` |
| 3 | 橙色 | `#F4D1A6` |
| 4 | 红色 | `#F1C2C2` |
| 5 | 紫色 | `#D9C7E8` |
| 6 | 灰色 | `#D5DADF` |

颜色只是用户自定义分类，不内置“力量、有氧、休息”等固定语义。已完成卡片采用勾选标记和克制的弱化样式，不能只依赖颜色表达状态。

### 3.4 编辑交互

- 单击日期卡片进入编辑状态。
- 编辑卡片在原位置扩展并覆盖必要的相邻空间，其他日期卡片不重新排列。
- 编辑区包含多行文本、6 色选择、完成状态和保存命令。
- 单击完成勾选框只切换状态，不触发编辑展开。
- 保存、单击组件空白处或切换到其他日期时收起编辑状态。
- 文本变更停止约 250 毫秒后自动保存；收起编辑区、翻页和退出时强制提交待保存内容。

### 3.5 复制功能

- 日期卡片菜单提供“复制到下周同一天”。
- 周菜单提供“复制本周到下一周”。
- 复制内容包括文本和任务色，目标日期默认重置为未完成。
- 目标已有内容时，必须显示确认信息；用户确认后才整体覆盖目标日期。
- 整周复制逐日执行同样规则，并在操作前统一列出将被覆盖的日期。

### 3.6 外观设置

- 组件背景为统一的全局设置，不允许每一天覆盖组件背景。
- 首版提供浅色和深色两种可读背景方案，不提供任意背景取色器。
- 背景透明度使用 `40%–100%` 滑块调节。
- 任务卡片继续使用固定 6 色，不受组件背景透明度影响到无法阅读。
- 界面必须根据背景方案自动使用具有足够对比度的文字和边框。

## 4. 系统托盘与设置

系统托盘菜单包含：

- 显示组件。
- 锁定或解锁组件。
- 开启或关闭开机自启动。
- 打开设置。
- 手动检查更新。
- 退出程序。

安装后默认开启开机自启动，用户可以随时关闭。退出表示结束进程；关闭设置窗口或收起桌面组件不能隐式退出后台进程。

设置页包含：

- 背景方案与透明度。
- 窗口位置和尺寸重置。
- 锁定状态。
- 开机自启动。
- 数据导出和导入。
- 检查更新。
- 版本、许可证和 GitHub 项目链接。

## 5. 数据设计

### 5.1 存储位置

- 计划数据使用本地 SQLite 数据库。
- 设置使用本地版本化配置文件。
- 数据和配置保存在当前 Windows 用户的应用数据目录。
- 软件不要求账号，不上传计划内容，不内置云同步。

### 5.2 计划记录

计划表至少包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` | ISO 日期 | 主键，对应本地日历日期 |
| `text` | 文本 | 用户输入的多行计划 |
| `color_id` | 整数 | 1 至 6 |
| `is_completed` | 布尔值 | 完成状态 |
| `updated_at_utc` | 时间戳 | 最后修改时间 |

空文本、未完成且使用默认颜色的日期不需要保留数据库记录。

### 5.3 设置记录

设置至少包含：

- 配置版本号。
- 窗口位置和尺寸，使用设备无关像素。
- 显示器标识和上次可见工作区。
- 锁定状态。
- 背景方案和透明度。
- 开机自启动状态。
- 上次自动检查更新的时间。

### 5.4 备份与恢复

- 导出文件为带格式版本号的 UTF-8 JSON 文件。
- 导出包含全部计划和用户设置，但不包含诊断日志。
- 导入是完整恢复，不与当前数据合并。
- 导入前自动创建当前数据的恢复副本。
- 文件损坏、格式未知或版本不兼容时拒绝导入，并保留现有数据。
- 数据库结构升级和导入操作使用事务。

## 6. 软件架构

首选技术路线为 C#、WPF 和 .NET 10。正式实现前必须先完成桌面层与性能原型。

建议模块边界：

| 模块 | 职责 |
| --- | --- |
| 桌面组件界面 | 两周布局、卡片状态、编辑和外观呈现 |
| 计划服务 | 日期查询、保存、完成状态、单日和整周复制 |
| 数据存储 | SQLite 事务、迁移、导入、导出和恢复副本 |
| 设置服务 | 配置验证、窗口状态和用户偏好 |
| Windows 集成 | 桌面层、托盘、单实例、自启动、多显示器和快捷方式 |
| 更新检查 | 查询 GitHub Releases 并比较版本 |
| 诊断日志 | 本地限额日志，不记录计划正文 |

界面不能直接读写 SQLite 或注册表。所有持久化操作通过服务边界完成，以便单元测试和后续替换实现。

## 7. Windows 集成和降级策略

- 桌面层实现允许使用受控的 Win32 互操作。
- Windows 资源管理器重启后，程序应自动重新连接桌面宿主。
- 桌面挂载持续失败时，降级为普通的无边框、非置顶窗口，而不是隐藏或退出。
- 托盘入口在桌面挂载失败时仍保持可用。
- 多显示器恢复必须校验窗口矩形，确保至少主要操作区域处于可见工作区。
- 自启动只为当前 Windows 用户注册。

## 8. 安装、更新和 GitHub 发布

- 采用当前用户安装，不请求管理员权限。
- 默认安装到当前用户的应用程序目录。
- 安装程序创建当前用户的桌面快捷方式、开始菜单入口和卸载入口。
- 安装完成后默认启用当前用户开机自启动。
- 卸载时清除程序、快捷方式和自启动项。
- 卸载默认保留计划数据，并提供“同时删除个人数据”的明确选项。

GitHub 仓库公开，采用 MIT 许可证。GitHub Actions 负责构建、测试和发布检查。GitHub Releases 至少包含：

- x64 安装包。
- 版本说明。
- 安装包校验值。

软件每天最多自动检查一次 GitHub Releases。发现新版本时仅提示并打开下载页，不自动下载或安装。网络失败不影响正常使用；只有手动检查失败时才主动显示错误。

## 9. 异常处理与隐私

- 保存使用事务，并在应用退出前刷新待写入内容。
- 数据库升级和导入前创建恢复副本。
- 数据库损坏时保留原文件，提示用户恢复备份或创建新数据库，不静默覆盖。
- 无法保存时在界面提供明确错误，并保留内存中的未保存文本，允许重试或导出。
- 诊断日志保存在本机、轮转并限制总大小。
- 日志不得包含计划正文、导入文件内容或用户目录之外的无关信息。
- 不采集遥测、使用统计或崩溃上传。
- 除 GitHub 更新检查外不主动联网。

## 10. 性能验收标准

性能基线测试机使用 x64 四核 2.0 GHz 或更高处理器、8 GB 内存、SSD、1920×1080 分辨率，并分别覆盖 100% 和 150% DPI 缩放。操作系统为 Windows 10 22H2、Windows 11 24H2，以及发布时最新的稳定 Windows 11 版本。

- 冷启动至组件可交互不超过 2 秒。
- 空闲 CPU 平均低于 0.5%。
- 空闲内存工作集目标不超过 180 MB。该门槛基于已批准的 WPF 原型实测结果调整，仍需在最终 Windows 测试矩阵中复测。
- 压缩安装包目标不超过 80 MB。
- 安装目录目标不超过 150 MB，包括应用私有运行时依赖，不计算 Windows 自带或系统共享组件。
- 编辑计划后 300 毫秒内完成本地保存，不出现可感知界面阻塞。
- 翻页、调整透明度和缩放组件时无明显卡顿。

桌面层原型必须在正式功能开发前验证启动、CPU、内存和打包体积，并在当前开发环境验证桌面挂载与显式降级路径。Windows 10 22H2、Windows 11 24H2 和发布时最新稳定 Windows 11 的完整手工矩阵保留为阶段 3 发布阻断项，不得因进入主功能开发而视为已通过。

## 11. 测试范围

### 11.1 自动化测试

- 周一边界、跨月、跨年和夏令时环境下的两周日期计算。
- 前后翻页与回到今天。
- 自动保存、退出刷新和事务回滚。
- 完成状态与固定颜色验证。
- 单日和整周复制、覆盖确认规则。
- 导出、完整导入、损坏文件拒绝和版本迁移。
- 设置验证、窗口可见区域修正和更新版本比较。

### 11.2 Windows 集成测试

- 当前用户安装、桌面快捷方式、开始菜单和卸载。
- 默认自启动、关闭自启动及卸载清理。
- 单实例和托盘菜单。
- 锁定、拖动、缩放和重启恢复。
- 多显示器切换、显示器断开和不同 DPI 缩放。
- 休眠恢复、资源管理器重启和桌面挂载降级。
- Windows 10 22H2、Windows 11 24H2，以及发布时最新的稳定 Windows 11 版本。

### 11.3 性能测试

- 冷启动时间。
- 空闲 CPU 和内存。
- 安装包与安装后体积。
- 保存延迟和连续编辑响应。

## 12. 首版明确排除

- 账号、云同步和多人协作。
- OneDrive 内置集成。
- 训练提醒、闹钟和 Windows 通知。
- 动作、组数、重量、时长等结构化训练字段。
- 复杂周期规则或自动生成计划。
- 任意任务取色器。
- 自动下载或静默安装更新。
- 多语言。
- 移动端和网页端。
- 遥测和远程崩溃收集。
- 同时运行多个组件实例或每个显示器各显示一个实例。

## 13. 首版完成定义

只有同时满足以下条件，首版才视为完成：

1. 所有核心交互、数据、安装和 Windows 集成功能通过验收。
2. Windows 10 22H2 和 Windows 11 x64 的安装与基本工作流测试通过。
3. 性能指标完成测量，未达标项已解决而不是仅记录。
4. 数据导入导出和异常恢复经过破坏性测试。
5. GitHub 仓库包含源码、MIT 许可证、构建说明和用户说明。
6. GitHub Releases 提供可安装的软件包、版本说明和校验值。

本规格批准后，下一阶段只编写分步实施计划；未经再次确认，不直接开始程序构建。
