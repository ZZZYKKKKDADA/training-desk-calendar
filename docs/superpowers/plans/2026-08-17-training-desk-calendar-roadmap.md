# 训练桌历实施路线图

设计规格：[2026-08-17-training-desk-calendar-design.md](../specs/2026-08-17-training-desk-calendar-design.md)

项目按风险和可验证成果拆成四个阶段。每个阶段开始前编写独立的详细实施计划；上一阶段的验收结果是下一阶段的输入。

## 阶段 0：Windows 桌面层与性能原型

详细计划：[2026-08-17-training-desk-calendar-prototype.md](2026-08-17-training-desk-calendar-prototype.md)

目标：用最小 WPF 程序验证桌面层挂载、资源管理器重连、窗口降级、多显示器恢复、DPI 行为、冷启动、空闲 CPU/内存和发布体积。

完成门槛：自动性能测试达到已批准指标，当前开发环境验证桌面挂载、显式降级和位置恢复，且选定 .NET 10 发布方式。完整 Windows 版本、DPI、Explorer 重启、休眠和多显示器手工矩阵记录为待办，并在阶段 3 发布前全部通过。

## 阶段 1：核心领域与本地数据

目标：实现两周日期计算、计划记录、完成状态、固定色板、自动保存、单日/整周复制、SQLite 事务、设置、导出/导入和恢复副本。

完成门槛：领域与存储测试全部通过；无需桌面窗口即可在测试中验证全部数据规则。

## 阶段 2：完整桌面体验与 Windows 集成

目标：实现已批准的两周界面、原位编辑、拖动缩放、锁定、托盘、单实例、自启动、设置窗口、多显示器和桌面层降级。

完成门槛：核心用户流程、Explorer 重启、休眠恢复、DPI 和多显示器场景通过集成验收。

## 阶段 3：安装、更新、发布与最终验收

目标：完成当前用户安装器、快捷方式、卸载数据选项、GitHub Releases 更新检查、GitHub Actions、说明文档、性能复测和发布资产。

详细计划：

- [Phase 3A 当前用户安装器](2026-08-17-training-desk-calendar-phase3a-installer.md)
- [Phase 3B GitHub 更新与发布](2026-08-17-training-desk-calendar-phase3b-github-updates.md)
- [Phase 3C 最终 Windows 验收](2026-08-17-training-desk-calendar-phase3c-final-validation.md)

完成门槛：Windows 10 22H2、Windows 11 24H2 和发布时最新稳定 Windows 11 的安装与端到端验收通过，GitHub Release 资产满足规格。

## 执行原则

- 每个行为先写失败测试，再写最小实现。
- 每个任务形成独立提交，提交前运行相关测试。
- 不在原型阶段加入计划编辑、数据库、托盘或安装器等生产功能。
- 不因实现困难降低规格中的性能、隐私或恢复要求。
- 任何阶段发现规格矛盾时先更新规格并获得确认，再继续实现。

## 规格覆盖

| 规格范围 | 承担阶段 |
| --- | --- |
| 技术路线、桌面挂载、降级、多显示器、性能基线 | 阶段 0 |
| 日期规则、计划数据、复制、自动保存、SQLite、设置、备份恢复 | 阶段 1 |
| 两周界面、原位编辑、外观、锁定、托盘、单实例、自启动 | 阶段 2 |
| 当前用户安装、卸载、更新检查、GitHub Actions、Releases、最终测试 | 阶段 3 |
| 隐私、日志、错误恢复和明确排除项 | 所有阶段持续检查，阶段 3 最终验收 |
